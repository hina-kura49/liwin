Tiling windows for GNOME, without leaving GNOME.

liwin brings the i3 / AeroSpace way of working to the stock GNOME Shell: windows tile themselves as they open, and you focus, move and re-arrange them from the keyboard. No new desktop, no new session.

When you'll use it

liwin is for people who think in keys, not in drag handles.

↩

You came from i3, sway or AeroSpace

You miss tiling, but you want to keep stock Ubuntu or Fedora GNOME — its settings, notifications, screen sharing and updates. Install liwin and keep your muscle memory: the default keys follow AeroSpace (Alt+H/J/K/L).

⌨

A coding layout without dragging

Open your editor, a terminal and a browser — they split the screen on their own. Alt+Shift+L pushes the terminal right, Alt+/ flips the split from side-by-side to stacked. One key, no mouse.

▣▣

Several monitors, several workspaces

Every GNOME workspace on every monitor gets its own tiling. Keep chat on workspace 3 and docs on 2; Alt+1…9 jumps there, Alt+Shift+2 sends the focused window along.

$_

Scripting your desk

Everything goes through a D-Bus service. Call liwin focus left or liwin move-node-to-workspace 2 from a shell script, a GNOME custom shortcut or busctl, and build the layout you want after git clone.

Features

Automatic tiling

Windows are tiled per GNOME workspace and monitor as they open and close. Dialogs and fixed-size windows float.

Keyboard-driven

Focus, move, layout and workspace commands, bound in an AeroSpace-style liwin.toml. Works with no config at all.

Plays nice with GNOME

Runs on top of the stock GNOME Shell. Keys GNOME already uses are skipped and logged, never stolen.

Scriptable

A documented D-Bus API (io.github.liwin.Daemon1) and the liwin command share one command language.

Small and safe

The tiling logic lives in a Rust daemon; the Shell extension is a thin layer. Window titles and app ids never leave the Shell.

Free & open source

Daemon and CLI under MIT or Apache-2.0, the extension under GPL-2.0-or-later. Signed build provenance on every release.

Default keybindings

Built in, so liwin works right after install. Put your own in ~/.config/liwin/liwin.toml (AeroSpace key names).

KeysAction
Alt+H / J / K / LFocus the window left / down / up / right
Alt+Shift+H / J / K / LMove the focused window left / down / up / right
Alt+/Toggle the split between horizontal and vertical
Alt+1 … 9Switch to workspace 1 … 9
Alt+Shift+1 … 9Move the focused window to workspace 1 … 9
 
# ~/.config/liwin/liwin.toml — replaces the built-in keys
config-version = 2

[mode.main.binding]
alt-h = 'focus left'
alt-shift-l = 'move right'
alt-slash = 'layout tiles horizontal vertical'
alt-1 = 'workspace 1'

Install

Needs GNOME Shell 50 on Wayland (Ubuntu, Fedora, Arch, …), x86_64 or aarch64. Installs for your user only — no root.

One-liner

curl -fsSL https://github.com/hina-kura49/liwin/releases/latest/download/install.sh | bash

It downloads the latest release, checks SHA256SUMS, puts liwin and liwin-daemon in ~/.local/bin, installs the extension, and adds a systemd user unit that starts the daemon with your session. Then log out and back in.

Downloads

  • liwin-linux-x86_64.tar.gz daemon + CLI, Intel / AMD
  • liwin-linux-aarch64.tar.gz daemon + CLI, ARM64
  • liwin@kura.shell-extension.zip GNOME Shell extension
  • SHA256SUMS checksums

Manual install

# 1. daemon + CLI
tar -xzf liwin-linux-x86_64.tar.gz
install -m 755 liwin-*/liwin liwin-*/liwin-daemon ~/.local/bin/

# 2. extension
gnome-extensions install --force liwin@kura.shell-extension.zip

# 3. log out and back in, then
gnome-extensions enable liwin@kura
liwin-daemon &   # or start it from a systemd user unit

You can also turn the extension on and off in the Extensions app. Remove everything with curl -fsSL https://github.com/hina-kura49/liwin/releases/latest/download/install.sh | bash -s -- --uninstall.

FAQ

Which GNOME versions are supported?

GNOME Shell 50 on Wayland. The extension declares shell-version: ["50"]; other versions are not tested yet. X11 sessions are not supported.

Is this a new window manager or a new session?

No. You keep the stock GNOME Shell and log in as usual. A small extension reports windows and moves them; the tiling decisions are made by liwin-daemon, a separate program that talks to it over D-Bus.

Will it break my GNOME shortcuts?

No. Keys already taken by GNOME are skipped and reported in the daemon log (journalctl --user -u liwin), never stolen. Choose other keys in liwin.toml.

How is it different from Pop Shell or Forge?

liwin follows i3 / AeroSpace semantics and config, keeps the extension minimal, and puts the logic in a tested Rust daemon you can drive from scripts over D-Bus.

Nothing happens after installing.

Log out and back in first: GNOME on Wayland only loads new extensions at login. Then check gnome-extensions info liwin@kura (should be ENABLED) and systemctl --user status liwin.

Does liwin collect any data?

No. Nothing leaves your machine, and window titles and app ids are not even sent to the daemon.
